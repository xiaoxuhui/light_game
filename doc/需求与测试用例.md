## 一、产品需求

### 1. 产品定位

- 名称：光的游戏（仓库 `light_game`）。
- 类型：**网格制光路解谜**。用光学元件控制光的方向与颜色，把正确颜色的光送到目标。无计时、无战斗、无失败。
- 形态：单页浏览器小游戏，电脑端优先（鼠标 + 键盘），同时兼容触摸设备。
- 完全离线：不联网、无后端、无账号、无统计上报。
- 零运行时依赖：不使用打包器、不引 npm 运行时包、不引 CDN。

### 2. 与《RAX》的对应关系

| RAX 的能力 | 本项目第一版 | 说明 |
|---|---|---|
| 网格光路、水平/垂直/斜向传播 | ✅ 做 | 8 方向传播 |
| 镜子、分光镜 | ✅ 做 | 反射镜、分光镜 |
| 颜色拆分与合成 | ✅ 做 | 二向色镜（拆分）+ 目标处加色合成 |
| 延迟镜、冷热镜、单通镜、条件触发 | ❌ 不做 | 属第二版，需要引入时间步模型 |
| 蓝图 / 芯片封装 | ❌ 不做 | 依赖前两版稳定后再做 |
| 关卡模式 + 星级挑战 | ✅ 做 | 1★ 通关，2★/3★ 按元件数 |
| 自由实验室（Free Lab） | ❌ 不做 | 第二版 |
| Steam 成就、创意工坊 | ❌ 不做 | Web 版无平台依赖 |

**合规说明**：玩法机制不受版权保护，可以正常参考；但美术资源、音频、文案、关卡布局一律自行设计，不复制原作素材。

### 3. 交付形态

| 阶段 | 交付物 | 验收方式 |
|---|---|---|
| 一 | Web 版（静态站点） | `npm run serve` 与 `file://` 双通道可用 |
| 二 | 安卓 APK | 真机安装，断网可玩 |

### 4. 工程约束（为阶段二预留，不可违反）

这些约束存在的唯一理由是让阶段二打包 APK 不返工：

- 资源引用一律相对路径。绝对路径 `/xxx` 在安卓 WebView 里会解析到错误域名并 404 白屏。
- 不使用 ES Module（`type="module"`）。`file://` 下会被 CORS 拦截；脚本按 `<script defer>` 顺序加载。
- 交互一律用 Pointer Events。HTML5 拖放（`dragover` / `drop`）在安卓触摸端不触发。
- 文件导出必须收敛到单一函数 `downloadFile(name, blob)`。WebView 不支持 `Blob` + `<a download>`，
  安卓阶段要整体替换为 JS 桥调用；调用点收敛好了，届时只改一个函数。
- 随机性必须可注入种子，否则单测无法复现。
- 版本号在 `package.json`、页面展示与 CHANGELOG 三处保持一致（由 `tests/static-app.test.js` 断言）。

### 5. 运行时环境要求

- 现代浏览器：支持 Canvas 2D、Pointer Events、`ResizeObserver`、`localStorage`。
- Node.js 20.19+（仅开发与 CI 需要）。
- 目标视口：360×640 竖屏（手机）到 1280×800 横屏（桌面），含刘海安全区。

## 二、玩法需求

### 1. 核心循环

放置元件 → 光路实时求解 → 观察光是否以正确颜色到达目标 → 调整元件位置或朝向 → 全部目标点亮即通关。

- 无计时、无步数限制、无失败状态。玩家可以无限次试错。
- 每次改动元件后立即重新求解，不需要「运行」按钮。
- 教学关有引导文案；正片关卡只有目标与元件配额。

### 2. 颜色模型

采用 **RGB 加色模型**，每种颜色用 3 位掩码表示，光的合成为按位或：

| 代号 | 组成 | 说明 |
|---|---|---|
| `R` / `G` / `B` | 单色 | 光源只发单色 |
| `Y` | R + G | 黄 |
| `C` | G + B | 青 |
| `M` | R + B | 品红 |
| `W` | R + G + B | 白 |

- 同一束光的颜色在传播过程中**不变**，除非经过二向色镜被拆分。
- **颜色合成只发生在目标处**：从任意方向射入同一目标的各束光按位或合并，合并结果满足目标要求即视为点亮。
- 元件所在格不发生颜色合成（穿过同一格的两束光互不影响）。

### 3. 元件清单（第一版）

| 代号 | 名称 | 可旋转 | 可放置 | 规则 |
|---|---|---|---|---|
| `emitter` | 光源 | 否 | 否 | 关卡预设，固定位置、朝向与颜色（R/G/B 之一），不可删除 |
| `mirror` | 反射镜 | ✅ 2 态 | ✅ | 45° 镜面（`/` 或 `\`），关于镜面方向做镜像反射 |
| `splitter` | 分光镜 | ✅ 2 态 | ✅ | 入射光同时产生透射与反射两束，各保留原色 |
| `dichroicR` / `dichroicG` / `dichroicB` | 二向色镜 | ✅ 2 态 | ✅ | 反射**指定颜色**，其余颜色透射。实现颜色拆分 |
| `wall` | 墙体 | 否 | 否 | 关卡预设，吸收所有光，不可删除 |
| `target` | 目标 | 否 | 否 | 关卡预设，标注所需颜色，被满足时点亮 |

**二向色镜作为三种独立元件**（红/绿/蓝各一个），而不是「一个元件加一个换色按钮」：
放置时一次到位，避免二次编辑，也避免移动端长按/右键的复杂交互。

### 4. 传播与求解规则

- 光在**格心之间**沿 8 个方向之一传播：上、下、左、右、左上、右上、左下、右下。
- 进入一格后由该格元件的规则决定出射方向；空格的出射方向与入射方向相同。
- **反射规则（纯函数）**：设入射方向 `d`，镜面方向 `u`，出射方向 `d' = 2(d·u)u − d`。
  - 当 `d` 与镜面平行时 `d' = d`（沿镜面滑过，不改变方向）。
  - 当 `d` 与镜面垂直时 `d' = −d`（原路返回）。
  - 标准情形下形成 90° 转向。
- **分光镜**在入射方向上有两个出射：透射（保持 `d`）与反射（按镜面规则），两束颜色都与入射相同。
- **终止条件**：撞到墙体、离开网格边界、或状态重复。
- **防环剪枝**：同一格 + 同一方向 + 同一颜色只处理一次，避免分光镜构成的环路导致死循环。
- **安全上限**：单次求解最多处理 4096 个光段；超出则停止追踪并在控制台给出提示（视为光路过载，不影响其它关卡）。
- 求解是**幂等纯计算**：输入关卡 + 元件布局，输出光段列表与目标状态；相同输入必须得到完全相同的输出。

### 5. 关卡与星级

- 章节结构：**第 0 章（教学，4 关）** + **第 1 章（6 关）** + **第 2 章（6 关）**，共 16 关。
- 教学关依次引入：光直射与目标 → 反射镜 → 分光镜 → 二向色镜。
- 星级规则（每关独立计算，取历史最好成绩）：

| 星级 | 条件 |
|---|---|
| ★ | 所有目标被点亮 |
| ★★ | 在 ★ 基础上，已放置元件数 ≤ `par + 2` |
| ★★★ | 在 ★ 基础上，已放置元件数 ≤ `par` |

`par` 由关卡数据给出，是设计者验证过的最小元件数。

- 关卡解锁：前一关通关后解锁下一关；已通关的关卡可重复挑战以刷新星数。
- 总星数在关卡选择页顶部汇总展示（对应 RAX「满星印章」这类成就的统计需求）。

### 6. 交互与控制

| 操作 | 鼠标 | 键盘 | 触摸 |
|---|---|---|---|
| 选中元件 | 点击工具栏 | `1`–`5` 数字键 | 点击工具栏 |
| 选中橡皮 | 点击工具栏的橡皮 | `E` | 点击工具栏的橡皮 |
| 放置到空格 | 左键点击空格 | 方向键移动光标 + `Enter` | 点击空格 |
| 旋转已放置的元件 | 左键点击该元件 | 光标移到元件上按 `R` | 点击该元件 |
| 删除元件 | 右键点击元件，或选中橡皮后点击 | 光标移到元件上按 `Delete` / `Backspace` | 选中橡皮后点击元件 |
| 打开关卡列表 | 顶栏「关卡」 | 未选中任何元件时按 `Esc` | 顶栏「关卡」 |
| 取消当前选中 | — | `Esc` | — |
| 撤销 | 底栏「撤销」 | `Ctrl+Z` | 底栏「撤销」 |
| 重做 | 底栏「重做」 | `Ctrl+Shift+Z` 或 `Ctrl+Y` | 底栏「重做」 |
| 清空本关 | 底栏「清空」（**连点两次**确认） | — | 底栏「清空」（仅在有元件时可用） |
| 保存 / 载入工作台 | 底栏「工作台」 | — | 底栏「工作台」 |
| 导出 / 导入关卡 | 底栏「导出」/「导入」 | — | 底栏「导出」/「导入」 |

- **`Esc` 是三态的**，优先级不可换：浮层已打开 → 关浮层；否则有选中元件 → 取消选中；
  否则 → 打开关卡列表。因此「关掉工具选中」这一下之后，再按 `Esc` 会弹出关卡列表。
- 撤销栈只记录元件布局快照，上限 100 步；执行新操作时砍掉原有的重做分支。
- 清空采用**两步确认**（3 秒内再点一次），超时自动解除，避免触摸端误触清光布局。

- 工具栏只显示该关允许使用的元件，并显示剩余配额（如「分光镜 ×1」）。
- 配额用尽后对应的工具栏项置灰不可选；**橡皮不受配额限制**，没有可删元件时置灰。
- 元件放置采用「吸附到格心」，不存在半格或自由坐标。
- 触摸端不依赖右键与悬停：因此删除操作有独立的「橡皮」工具，而不是靠再次点击或长按。
- 目标被满足时必须有明确的视觉与音效反馈（音效为第二版内容，第一版只做视觉）。

### 7. 存档与导入导出

- **自动存档**：每次元件增删改后写入 `localStorage`，记录每关的元件布局、历史最好星数、解锁进度。
- **手动存档点**：工具栏提供「保存工作台」，把当前关卡的布局存为具名快照。对应 RAX「存一下」成就的需求。
- **导入导出**：关卡数据统一用 JSON，页面支持导出当前关卡文件与导入外部关卡文件。
- 导入必须做**完整校验**（schema 标识、版本号、字段类型、坐标范围、颜色代号合法性、元件类型白名单、规模上限），
  任一项不通过则整体拒绝并给出具体原因，不做部分导入。
- 存档格式一旦随正式版发布，后续变更必须提供迁移路径。

## 三、第一版范围边界

**做**：16 关、6 类元件、8 方向传播、颜色拆分与合成、星级判定、自动存档、JSON 导入导出、键盘与触摸可达。

**不做**（明确排除，避免范围蔓延）：

- 时间维度相关的任何机制（延迟镜、脉冲光源、逐帧演化）。
- 蓝图 / 芯片封装与分享。
- 自由实验室（Free Lab）。
- 关卡编辑器（导入外部 JSON 不等于内置编辑器）。
- 多语言、音效、成就系统、排行榜、云存档。

| 指标 | 取值 | 实测 |
|---|---|---|
| 网格规模上限 | `4 ≤ cols, rows ≤ 40`（`MIN_SIDE` / `MAX_SIDE`） | 内置关卡实际最大 12×7；40×40 可正常求解与绘制 |
| 单关元件数上限 | 999（`MAX_UNITS`，含预设元件；导入校验逐项拒绝超限） | 极限关卡 998 个分光镜通过校验 |
| 单次求解光段上限 | 4096（`MAX_SEGMENTS`），超出置 `overflow` 并停止追踪 | 40×40 铺满分光镜时稳定顶到 4096 |
| 单帧耗时上限 | 求解 + 绘制 < 16.7 ms（60 fps 预算的一半） | 内置关卡：求解 < 0.005 ms（低于计时器分辨率）、绘制 0.02 ms；极限关卡（998 元件 / 4096 光段）：求解 6.4 ms、绘制 0.8 ms |
| 内置关卡规模 | 最大 12×7、最多 3 类元件 | 求解与绘制合计远低于 0.1 ms |

结论：**不需要优化求解器**。最坏情况（几何上限 40×40 + 元件数上限 + 光段数上限三者同时打满）
也只有约 7.2 ms，仍在 60 fps 的单帧预算内。`overflow` 这条降级路径保留，因为它在
40×40 铺满分光镜时是**真实可达**的（不是理论防御），所以必须有对应的 UI 提示（U12）。
