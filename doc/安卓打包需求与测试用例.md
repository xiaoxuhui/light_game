# 安卓打包需求与测试用例

把「光的游戏」打包为可安装的安卓 APK：极简 WebView 外壳 + 内置网页资源，
云端构建 debug 包，完全离线可用。本文定义验收标准与用例，实施步骤见
[安卓打包实施计划](./安卓打包实施计划.md)。

## 1. 目标与范围

| 项 | 内容 |
|---|---|
| 目标 | 手机/平板可安装的 APK，玩法与网页端一致，无需网络 |
| 包名 | `com.xiaoxuhui.light` |
| 应用名 | 光的游戏 |
| minSdk / targetSdk | 24（Android 7.0）/ 34 |
| 版本 | versionName `1.1.0`，versionCode `1` |
| 签名 | debug（首版直接安装，不折腾正式签名） |
| 分发 | GitHub Release 挂载 APK |

**不在本期范围**：纯血鸿蒙 NEXT（需 HAP）、原生能力（相机/推送）、正式签名上架、
应用内手柄（游戏已全程 Pointer Events，无需改交互）。

**版本号说明**：APK 版本（`1.1.0`）比 Web 版本（package.json `1.0.0`）高一档，
两者各自演进；Web 端三处版本号一致性仍由 `tests/static-app.test.js` 把关，
Android 侧由 `tests/android-shell.test.js` 把关。

## 2. 网页形态判定

入口 `index.html` 以相对路径引用 6 个 `scripts/*.js`（`light-core` → `light-engine`
→ `levels` → `renderer` → `storage` → `app`，`<script defer>` 顺序即依赖顺序）
与 `styles/main.css`，属于 **B 类：多文件静态站**。因此同步策略为：

```
index.html → assets/index.html
scripts/   → assets/scripts/
styles/    → assets/styles/
```

入口页与 `MainActivity.ASSET_FILE` 必须同为 `index.html`。

**无需改 `base` 路径**：全站引用均为相对路径，WebView 里以
`https://appassets.androidplatform.net/assets/index.html` 加载后能正确解析。

## 3. 能力适配清单

| 网页能力 | WebView 表现 | 外壳处理 | 涉及位置 |
|---|---|---|---|
| `localStorage`（星数、每关布局、工作台快照） | 需开启 domStorage | `domStorageEnabled = true` + 固定 https 域保证 origin 稳定 | MainActivity |
| `Blob` + `<a download>` 导出关卡 | **静默失败** | `downloadFile()` 内检测 JS 桥，命中则把文本交给原生写系统下载目录 | `storage.js` 单一出口 |
| `<input type="file">` 导入关卡 | 无反应 | 实现 `onShowFileChooser` | `app.js` 的 `#file-import` |
| 触摸放置/旋转元件 | 正常（Pointer Events） | 无需改动 | — |
| Canvas 2D 渲染 | 正常 | 无需改动 | — |
| 键盘操作（`1`–`5`、方向键、`Ctrl+Z`） | 无物理键盘时不适用 | 不处理，全部操作都有触摸等价路径 | — |

**导出路径只有一处**：`exportCurrentLevel()` → `storage.downloadFile(name, blob)`。
这是 v1.0.0 就收敛好的设计，安卓阶段只需改这一个函数，调用点零改动。

导出文件名沿用网页端逻辑：`levelFileName(level)` → `<关卡 id>.json`（如 `t02.json`）。

## 4. 验收用例

### 4.1 构建与结构（无需真机）

| 编号 | 用例 | 预期 |
|---|---|---|
| U01 | `npm run check:android` | assets 与源逐字节一致，退出码 0 |
| U02 | `npm test` 中的安卓结构断言 | 包名/命名空间/SDK/版本/应用名/桥名/入口文件名全部匹配 |
| U03 | APK 内 `assets/index.html` 与仓库 `index.html` | `cmp` 通过，字节一致 |
| U04 | CI 构建 | Android APK workflow 通过，产出 `app-debug.apk` |

### 4.2 安装与启动

| 编号 | 用例 | 预期 |
|---|---|---|
| U05 | 安装 APK | 允许「未知来源」后可正常安装，无失败提示 |
| U06 | 首次启动 | 直接进入第 0 章第 1 关，无白屏、无黑屏闪动 |
| U07 | 飞行模式启动 | 可正常启动并完整通关（全离线） |
| U08 | 桌面图标 | 显示光路图标与「光的游戏」名称，自适应图标不变形 |
| U09 | 权限检查 | 系统设置中无任何权限申请（尤其无网络权限） |

### 4.3 功能一致性

| 编号 | 用例 | 预期 |
|---|---|---|
| U10 | 网格渲染 | 网格、光路、配色与网页端一致（深色底 `#08090c` + 暖金光路） |
| U11 | 放置与旋转元件 | 点工具栏选中元件 → 点网格落下 → 点已放元件旋转，全流程可用 |
| U12 | 关卡导航 | 顶栏「关卡」打开列表，按章节分组，未解锁置灰；通关后能进下一关 |
| U13 | 数据持久化 | 通关得星、放置布局、保存工作台后杀进程重进，全部仍在 |
| U14 | 导出关卡 JSON | 点导出**不下载**，改为提示「已保存到下载/…」，文件可在系统下载目录找到且 JSON 合法 |
| U15 | 导入关卡 JSON | 点导入弹出系统文件选择器，选中后布局正确应用；导入被篡改的文件时逐条列出错误且不切关 |

### 4.4 屏幕与交互

| 编号 | 用例 | 预期 |
|---|---|---|
| U16 | 旋转屏幕 | 不重建 Activity，当前关卡与布局不丢失 |
| U17 | 手机竖屏 | 工具栏不压到网格上，画布不被挤成 0，每个工具都在视口内 |
| U18 | 平板横屏 | 布局正常，画布充分利用空间 |
| U19 | 刘海/系统栏 | 顶部不被状态栏或挖孔遮挡，底部不被导航栏遮挡 |
| U20 | 返回键 | 优先回退网页历史；无历史时退出应用 |

## 5. 通过标准

- U01–U04 必须全过（构建期守门，CI 自动执行）。
- U05–U20 需真机验证，允许个别项标注为「已知限制」并说明原因。
- 已知设计取舍：导出走系统下载目录而非浏览器下载（WebView 不支持 Blob 下载），
  用户感知为「提示已保存」而非「弹出下载」。
