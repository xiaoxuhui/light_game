证书字段：

| 字段 | 值 | 判断 |
|---|---|---|
| `subject` | `CN=Light Game Debug, O=xiaoxuhui, C=CN` | 是项目自己的名字，**不是** `CN=Android Debug, O=Android, C=US`（后者意味着构建机现生成的随机 key） |

| `notAfter` | `Sep 11 06:49:13 2056 GMT` | 30 年有效期 |

两条判据都指向「签名已固定」。**v1.2.0 与 v1.2.1 同签名 ⇒ 可覆盖安装**，
这是 v1.2.0 发布时还不具备的验证条件。

> **一个容易误判的点**：这个 APK 的 `META-INF/` 里**没有** `CERT.RSA` / `CERT.SF` / `MANIFEST.MF`。
> 这不是没签名 —— `minSdk = 24` 时 AGP 会自动跳过 v1（JAR）签名，
> 证书只存在于 APK Signing Block 的 v2 方案里。核对签名要解析签名块，别在 `META-INF/` 里找。

## 4. 已知限制（属设计取舍，不是缺陷）

| 项 | 说明 |
|---|---|
| debug 签名 | 仍用 debug 签名分发，便于直接安装；代价是部分系统提示「来源不安全」。签名**已固定**，不影响覆盖升级 |
| 存档不互通 | 安卓端 page 跑在 `appassets.androidplatform.net` 的 https 域下，`localStorage` origin 与网页版不同，安卓端存档从零开始 |
| 无物理键盘 | 手机端不提供键盘操作，但所有操作都有触摸等价路径 |
| 导入授权不持久 | 走系统文件选择器，选中文件读完即止，下次需重新选 |

## 5. 本轮是怎么核对的（可复现）

本机没有 JDK / Android SDK / aapt，用 Python + openssl 完成全部四项：

```bash
# ① 下载并比对哈希（对照 Release 的 digest 字段）
curl -sL -o apk.zip https://github.com/xiaoxuhui/light_game/releases/download/v1.2.1/light-game-android-1.2.1-debug.apk
sha256sum apk.zip

# ② 包内二进制 Manifest 的 versionCode / versionName
python apk-manifest.py apk.zip

# ③ 提取 v2 签名证书，与仓库 keystore 逐字节比对
python apk-v2-cert.py apk.zip apk-cert.der
openssl pkcs12 -in android/app/debug.keystore -passin pass:android -nokeys -clcerts -out ks-cert.pem
openssl x509 -in ks-cert.pem -outform DER -out ks-cert.der
cmp apk-cert.der ks-cert.der && echo "签名一致"

# ④ assets 与仓库源逐文件比对（形态 B：逐个比 SYNC_ITEMS）
```

②③ 的脚本直接用 `web-app-to-android-apk` 技能 `templates/scripts/` 下那两个，无需自己写：

| 脚本 | 用途 | 两个必踩的坑 |
|---|---|---|
| `apk-v2-cert.py` | 从 APK Signing Block 取 v2 证书 | 块起始 = `magic偏移 + 8 - size`（`size` 含末尾 24 字节，漏算会错位 16 字节、看起来像"没有 v2 签名"） |
| `apk-manifest.py` | 读包内 `versionCode` / `versionName` | `versionName` 走字符串池、`versionCode` 走 int 字段，按同一种读法会得到 `None` |

**`versionCode` 只存在于 APK 内部** —— 文件名、git tag、Release 文案、`package.json` 写什么都不算数。
