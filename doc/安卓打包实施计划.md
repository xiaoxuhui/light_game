### 首轮红灯的两个根因（都值得记）

| 现象 | 根因 | 修法 |
|---|---|---|
| APK 构建挂在 `:app:mergeDebugResources` | `colors.xml` 的注释里写了 CSS 变量名 `--bg-deep`，而 **XML 规范不允许注释内出现连续两个减号**，aapt 直接拒绝 | 改写注释措辞（`bg-deep`）；补一条遍历资源 XML 的守卫断言，注入违规实测能拦，本地就能发现 |
| `test` 挂在「assets 与源一致」与「入口页存在」 | `assets/` 是本地产物（`android/.gitignore`），CI 上跑 web 测试前不会同步它 | 「目录不存在」≠「内容不一致」：目录不在时跳过这两条；CI 里另外显式同步一次，顺带覆盖同步脚本本身可用 |

两条的**共同点**：本机没有 Android 工具链，凡是只有 aapt / gradle 才能发现的错误，
都会一直拖到 CI 才暴露，而且首轮要等五分钟。所以凡是有纯文本替代方案的检查，
都下沉成单测断言 —— 目前的成果是「XML 注释含 `--`」这类坑不必再等 CI。

另一条：`strategy.matrix` 默认 `fail-fast: true`，所以一个 Node 版本失败会**取消**其它矩阵 job，
看起来像「三个都红」，实际只有一个真失败。定位时先看 `conclusion: failure` 的那个。

## 风险与已知取舍

| 项 | 说明 |
|---|---|
| 导出交互差异 | WebView 不支持 Blob 下载，改由 JS 桥写系统下载目录，提示语为「已保存到…」 |
| 无物理键盘 | 手机端不提供键盘操作，但所有操作都有触摸等价路径（工具栏点击 + 网格点击） |
| assets 逐文件列举 | `SYNC_ITEMS` 显式列出 8 个文件而非整目录复制。好处是不把开发工具打进包；代价是新增脚本时要手工加一行，风险由 `tests/android-shell.test.js` 的「index.html 引用的资源必须都在清单内」兜住 |
| 分支名限制 | 沙箱环境不支持含 `/` 的分支名，统一用 `feat-android-apk` |
| `file://` 与 https 域差异 | WebView 走 `appassets.androidplatform.net` 的 https 域，`localStorage` 的 origin 与 `file://` 不同；安卓端存档从零开始，属预期 |
| 图标不用图像模型 | 程序化绘制，风格完全可控且可复现，代价是不如 AI 生成的有质感。要换风格改 `tools/make-icons.py` 的配色与几何参数即可 |
