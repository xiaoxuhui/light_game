# 安卓打包实施计划

分阶段推进，每阶段一个 commit，便于回滚与 review。
验收标准见 [安卓打包需求与测试用例](./安卓打包需求与测试用例.md)。

技术版本组合**固定不变**（偏离易踩坑）：
AGP 8.5.2 + Gradle 8.7 + JDK 17 + compileSdk/targetSdk 34 + minSdk 24 +
androidx.webkit 1.11.0。

## 阶段 0：准备与形态分类

- [x] 确认网页形态：B 类多文件静态站（`index.html` + `scripts/` + `styles/`）
- [x] 确认无打包器产物，无需改 `base` 路径
- [x] 排查能力清单：`localStorage` 存档、1 处 Blob 导出、1 处 file 导入
- [x] 确认无 HTML5 拖放 / `type="module"` / `fetch` / 外链跳转（四条前置约束全过）
- [x] 基线测试通过（单测 95/95、e2e 60/60）
- [x] 基于 main 切出分支 `feat-android-apk`

> ⚠️ **环境注意**：本机沙箱环境**无法创建含 `/` 的分支名**（`git switch -c feat/android-apk`
> 会静默失败：打印 `Switched to a new branch`，但 `.git/refs/heads/feat/` 不生成）。
> 因此分支名改用 `feat-android-apk`。切分支后必须用 `git branch --show-current` 复核。

## 风险与已知取舍

| 项 | 说明 |
|---|---|
| 导出交互差异 | WebView 不支持 Blob 下载，改由 JS 桥写系统下载目录，提示语为「已保存到…」 |
| 无物理键盘 | 手机端不提供键盘操作，但所有操作都有触摸等价路径（工具栏点击 + 网格点击） |
| assets 逐文件列举 | `SYNC_ITEMS` 显式列出 8 个文件而非整目录复制。好处是不把开发工具打进包；代价是新增脚本时要手工加一行，风险由 `tests/android-shell.test.js` 的「index.html 引用的资源必须都在清单内」兜住 |
| 分支名限制 | 沙箱环境不支持含 `/` 的分支名，统一用 `feat-android-apk` |
| `file://` 与 https 域差异 | WebView 走 `appassets.androidplatform.net` 的 https 域，`localStorage` 的 origin 与 `file://` 不同；安卓端存档从零开始，属预期 |
| 图标不用图像模型 | 程序化绘制，风格完全可控且可复现，代价是不如 AI 生成的有质感。要换风格改 `tools/make-icons.py` 的配色与几何参数即可 |
