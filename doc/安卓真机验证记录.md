### 3.2 未逐项反馈

U07–U09、U13–U20 本轮没有逐项走查。其中 **U13（存档跨进程）** 与 **U14（导出落盘）**
是 WebView 与浏览器行为差异最大的两条，也是唯一无法靠浏览器 e2e 覆盖的部分，
建议按下面步骤各走一遍。

#### U13 存档跨进程

1. 进任意关卡，放几个元件，通关拿星。
2. 从最近任务列表里**划掉**应用（真正杀进程，不是退到后台）。
3. 重新打开应用，回到该关卡。

预期：布局与星数都还在。若丢失，先查 `scripts/storage.js` 的后端选择逻辑 ——
`localStorage` 不可用时会静默降级为内存存档，表现正是「重启即失」。

#### U14 导出落盘

1. 进任意关卡，点「导出」。

预期：弹出「已保存到…」提示，而不是浏览器那种下载条。

2. 打开系统「文件」/「下载」目录，找到刚导出的 JSON。

预期：文件在，内容合法，能被「导入」原样读回来。

## 4. 已知限制（属设计取舍，不是缺陷）

| 项 | 说明 |
|---|---|
| 无物理键盘 | 手机端不提供键盘操作，但所有操作都有触摸等价路径（工具栏点击 + 网格点击） |
| 存档不互通 | 安卓端页面跑在 `appassets.androidplatform.net` 的 https 域下，`localStorage` 的 origin 与 `file://`、网页版都不同，安卓端存档从零开始 |
| debug 签名 | 用 debug 签名发布是为了便于直接安装、免除密钥分发，代价是部分系统会提示「来源不安全」 |
| 导入授权不持久 | 走系统文件选择器，选中的文件读完即止，下次导入需要重新选 |
| 导出走下载目录 | WebView 不支持 `Blob` + `<a download>`，因此改由原生桥落盘，用户感知为「提示已保存」而非「弹出下载」 |

## 5. 出问题时先看哪里

| 症状 | 排查入口 |
|---|---|
| 启动白屏 | 资源是否相对路径引用 —— 绝对路径 `/xxx` 在 WebView 里会解析到错误域名并 404 |
| 导出无反应 | `storage.downloadFile()` 的桥探测是否命中 `LightAndroid`，再看 `MainActivity.saveFile()` 的落盘路径 |
| 存档丢失 | `storage.js` 的后端选择与 `SAVE_SCHEMA` 版本号 |
| 布局错乱 | 视口与安全区处理，`styles/` 里的响应式断点 |
| 旋转屏幕丢状态 | `MainActivity` 的 `configChanges` 配置 |

改动范围都可控：跨进程相关的只有 `android/app/src/main/java/com/xiaoxuhui/light/MainActivity.kt`
与 `scripts/storage.js` 两处。
