# 光的游戏：实施计划

## 目标

按「需求 → 设计 → 计划 → 实现 → 验证 → 发布」的流程，交付一个可离线运行的浏览器小游戏，
并在 Web 版稳定后打包成安卓 APK。

## 执行原则

- **规划先行**：动手写代码前先更新 `需求与测试用例.md` 与 `设计文档.md`。
- **每功能一个 commit**：前缀规范 `feat` / `fix` / `refactor` / `docs` / `test` / `ci` / `chore`。
  底层／接口先，上层／页面后；新模块先，集成后；文档独立。
- **测试驱动**：每个阶段的测试全绿才进下一阶段；前端改动必须做真实浏览器交互验证。
- **不为了让测试通过而编造规则**：产品规则不确定时停下来问，不猜。
- **小步快走**：每个阶段是一个可独立验收的闭环，完成后单独提交。
- **不扩大改动范围**：跑偏的发现记进本文件的待办，不顺手混进当前提交。
